About TREMER

1. What TREMER Does and How It Works

TREMER is a specialized computational biology tool designed to construct highly accurate phylogenetic trees. It builds an initial tree from Y-DNA STR (Short Tandem Repeat) values, and subsequently merges that STR tree with deterministic trees constructed from hard SNP (Single Nucleotide Polymorphism) data and genealogical records.

To handle the biological reality of hyper-mutable markers (which frequently back-mutate and confuse strict mathematical models), TREMER utilizes a sophisticated Two-Pass Architecture:

  • Phase 1 (The Structural Pass): The core engine builds the physical scaffolding of the tree using robust data overlap and majority rules, guaranteeing that branches, SNPs, and genealogical clusters are locked together with absolute structural integrity.
  • Phase 2 (The Parsimony Scrub): Once the structure is locked, a strict biological auditor sweeps the tree. If it detects highly improbable mutation loops (such as a mutation that immediately reverses across multiple child branches), it safely scrubs the false anomaly and pushes the mutation to the specific sub-branch that actually caused it.

This decoupling of structure and presentation results in a clean, biologically sound hierarchy.

2. What the Input Files Contain

TREMER accepts a single, dynamically named text file (e.g., Project_s1.txt) as input. This file contains block-tagged sections that provide the engine with the necessary genetic and historical data:

  • Markers and Modals: Lists of the specific STR markers being compared and the foundational ancestral values for the group.
  • SNP and GEN Hierarchies: Hard evidence defining the chronological order of known ancestors and haplogroup mutations.
  • Kit Data: The specific STR values, positive/negative SNP tests, and subgroup affiliations for every individual kit being analyzed.

3. The User Interface

The TREMER web interface is powered entirely by WebAssembly (Wasm). When you upload a file and click "Generate Tree," the raw C engine executes locally within your own web browser. This means your data is processed on your local CPU without being uploaded to a remote backend server, ensuring maximum privacy and speed.

Targeted Filtering: By default, TREMER will generate the full suite of visual trees and data tables for the entire project. However, if you specify a target Node or Kit ID in the interface before generating, the engine enters "Filtered Mode." In this mode, it bypasses the standard outputs and generates a customized Variant STR Marker table (HTML) specifically isolated to that kit's ancestral line.

Once processed, you can preview the generated files directly in your browser tab or download them to your hard drive.

4. What the Output Files Contain

Upon a successful execution, TREMER generates five highly-detailed output files:

  • tree[Group].txt: A hierarchical, text-based representation of the generated phylogenetic tree.
  • [Project]_s[Group].svg: A visual, graphic rendering of the phylogenetic tree featuring chronological scaling, junction boxes, and terminal STR mutations.
  • [Project]_s[Group].html: A comprehensive data table cross-referencing all kits against all tested STR marker values.
  • [Project]_b[Group].html: A filtered HTML table displaying only the variant STR markers (mutations) that deviate from the group's local modal baseline.
  • [Project]_g[Group].html: An HTML table displaying the positive/negative testing statuses of all kits for the provided GEN and SNP markers.
