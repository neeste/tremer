TREMER Tree Logic Rationale

TREMER constructs phylogenetic trees by combining hard biological truths (SNPs and genealogical paper trails) with probabilistic genetic markers (STRs). The core philosophy is "Strict Biological Skeletons," ensuring that predictive STR clustering never overrides established biological facts.

The tree-building process is executed in multiple distinct phases within the core engine (src/tree_logic.c):

1. Skeletal Construction & Kit Bucketing (build_skeleton_and_bucket_kits)

Before evaluating any STR mutations, TREMER establishes an absolute biological framework.

  • SNP Nodes (NODE_SNP): Trees are first populated with known terminal SNPs and their established hierarchy.
  • Genealogical Nodes (NODE_GEN): Paper-trail ancestors are inserted into the tree.
  • Merging: If a SNP node and a genealogical node represent the exact same biological branch (i.e., they contain the exact same set of kits or one is a pure subset without conflict), they are merged into a single NODE_MERGED to simplify the tree structure.
  • Bucketing: Each kit is evaluated against this skeleton. Using functions like is_acceptable_target, TREMER enforces absolute constraints: a kit must be placed in a branch that respects its positive SNPs, negative SNPs, and explicit genealogical assignments. It is fundamentally impossible for a kit to be pulled into an unrelated branch simply because its STRs look similar.

2. Modal Inference (initialize_modals_top_down, refine_modals_bottom_up)

With the skeleton established and kits securely bucketed, TREMER calculates the expected ancestral STR profile (the "modal") for every node in the tree.

  • Top-Down Initialization: The overall project modal is pushed down the tree as a baseline.
  • Bottom-Up Refinement: Starting from the leaves (the kits), the algorithm recalculates the modal for each parent node by determining the most frequent allele at each marker among its immediate descendants. This two-pass approach ensures that the ancestral signature at any given branching point is accurately inferred from the kits beneath it.

3. STR Branching ("The Shield" and Mutation Grouping)

Once modals are established, TREMER looks for shared mutations within the bucketed groups to create inferred STR branches.

group_shared_str_mutations

This function identifies specific STR markers where a mutation is shared by multiple descendants (nodes or kits) within a parent group.

  • The Shield: A critical piece of logic prevents STR clustering from forming branches that would disrupt known genealogical/biological relationships. For instance, if two known paper-trail sons share an STR mutation, they are not artificially clustered into a new intermediate STR node unless the temporal gap between the ancestor and the sons is large enough (>60 years) to biologically justify an intermediate ancestor.
  • When a valid shared mutation is found, a new NODE_STR_BRANCH is created, and the matching descendants are moved into it.

apply_rule_of_two

After major shared mutations are grouped, the "Rule of Two" is applied. This creates terminal STR branches (NODE_STR) if at least two kits within a remaining pool share a unique mutation away from the local modal. It ensures that solitary mutations (unique to a single kit) do not unnecessarily spawn new ancestral nodes.

4. Reassignment & Optimization (check_kits_and_reassign, reassign_root_orphans)

Initial bucketing can sometimes leave kits artificially stranded high up in the tree (e.g., at the ROOT) if their SNP testing is incomplete.

TREMER runs a reassignment loop to evaluate if these "orphaned" kits are a better genetic fit deeper in the tree. It calculates the STR distance between the kit and various nodes. However, this reassignment is strictly bounded by the skeletal rules. A kit will only be moved deeper if the new location does not violate any of its known negative SNPs or explicit genealogical boundaries.

(Note: In "Relaxed Mode", some of these strict biological boundaries are softened to allow for SAPP-style heuristic clustering based purely on STR similarity).

5. Parsimony Scrub (post_process_parsimony_scrub)

Tree-building algorithms can sometimes produce redundant "pass-through" nodes—a node with only one child and no kits of its own.

To ensure the tree remains parsimonious (the simplest structure that explains the data), this function performs a bottom-up scrub. If an inferred STR node serves only to pass a single line of descent down to another node without grouping any actual kits, it is structurally bypassed and its mutations are collapsed up into the parent. This keeps the visual output clean and genetically accurate without meaningless intermediate steps.

6. Age Estimation (estimate_str_node_ages)

Finally, TREMER estimates the ages of the newly inferred STR nodes. While SNP and GEN nodes often have hard dates (from FTDNA Discover or paper trails), STR nodes are dated proportionally based on the number of accumulated mutations relative to their bounding parent and child nodes.
